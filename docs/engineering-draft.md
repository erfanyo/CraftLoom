# 独立 Minecraft 引导项目：工程与协议草案

日期：2026-10-25。状态：设计草案，以下接口与独立项目功能尚未实现。
项目名称为 CraftLoom（织途），独立仓库远程地址待定。本文件由 AMCL 中的早期设计草案迁入；项目不依赖 AMCL。

## 1. 已确认范围

- 首发环境：Minecraft 1.20.1 Forge。1.12.2 Forge、1.7.10 Forge 必须后续覆盖，通过独立版本适配实现。
- 独立仓库、版本与发布流程；AMCL 为官方接入端，其他启动器可以手动安装。
- 对外提供 MCP；后续可包装 DeepSeek Harness、Claude Code 等接入方式，不假定其插件 API 相同。
- 游戏内呈现场景相关引导，Web 提供完整知识工作台，Agent 查询同一核心服务。
- 默认玩家主动请求；支持物品、具体配方与任务目标标记，以及订阅提醒。
- 附近容器按物品或标签查询，默认不通读；大型存储通过可选适配器查询。
- 知识记录来源、版本与冲突，交叉验证任务、运行时数据、资料和实际反馈；推荐不声称最优。
- 个人推理与截图分析在玩家侧进行；模型调用可选，普通资料查看不触发模型。
- 多人由房主/管理员发布知识库，玩家按需下载或完整缓存允许公开的内容。
- 玩家贡献未批准也可作为额外信息显示；管理员可确认、标记争议或失效，保留历史。
- 公共目标按权限同步；个人目标留在本地。手动完成后归档，可恢复；自动完成按创建时明确的条件判断。
- 告示牌作为方案锚点：先投影、检查，再由玩家单独决定是否触发搭建，不控制玩家移动。
- 搭建四档：关、投影、消耗物品搭建、不消耗物品搭建。服务端授权限制最高能力。
- 首版共享限定服务器内部，预留导入导出；AI 通关、多角色协作和 RTS 用法预留接口，后置实现。

## 2. 部署与模块边界

```text
游戏客户端 Mod ── MC 自定义消息 ── 服务端 Mod
      │                              │
 玩家本地核心服务                房主共享知识服务
      │                              │
 Web / AMCL / MCP                知识、贡献、公共目标
```

单机可由同一核心服务兼任个人与房主角色，数据分区仍然独立。局域网共享使用游戏连接；
专用服务器的共享服务通过本机受控接口连接服务端 Mod，无需默认开放额外公网端口。

| 模块 | 职责 |
| --- | --- |
| 客户端 Mod | 快捷键、短暂键位提示、上下文、截图、目标入口、界面箭头、投影 |
| 服务端 Mod | 实际游戏查询、权限校验、锚点与搭建任务、材料扣除和世界修改 |
| 本地核心服务 | 私人目标、知识缓存、检索、可选规划、模型凭据、用量与个人修正 |
| 房主共享服务 | 共享知识版本、贡献记录、公共目标及其权限；无需提供模型 |
| Web | 搜索、节点详情、双向关系、来源冲突、目标和方案管理 |
| MCP / 本地 API | 复用应用层能力；不会绕过玩家、服务端或资源权限 |

推荐仓库布局（逻辑模块，不要求首版各自成为独立进程或发布包）：

```text
protocol/                 消息定义、错误、能力与兼容样例
game/common/              可跨版本复用的纯逻辑
game/forge-1.20.1/        首发适配
game/forge-1.12.2/        后续适配
game/forge-1.7.10/        后续适配
integrations/             配方查看器、任务、机器与存储适配
core/                     应用服务、知识、目标、任务调度
web/                      知识工作台
connectors/                MCP、AMCL 及后续平台接入
schemas/                  知识与方案数据格式
tests/fixtures/           跨版本协议与典型整合包样例
docs/                     安装、协议、贡献、兼容矩阵
```

技术栈已确定为 Java 游戏端、Python 3.12/FastAPI/Pydantic 核心、TypeScript/React/Vite Web、SQLite 加受控文件目录；本地使用 HTTP/WebSocket，预留 Rust 热点计算接口。详见 technology-decisions.md，首版不要求向量库或云服务。

## 3. 身份与数据模型

名称用于搜索，不作为唯一身份。统一实体引用包含类型、注册名和适用上下文。

- 环境：MC、加载器、Mod 清单和版本，以及相关配置/脚本/数据包指纹。
- 物品：注册名、旧版 metadata、必要 NBT 或组件；区分物品类型与具体堆栈。
- 配方：运行时 ID；旧版没有稳定 ID 时由适配器生成带来源的规范化键，不能冒充原生 ID。
- 世界/服务器：本项目持久化标识；服务器名称或地址不作为世界唯一身份。
- 目标：所有者、可见范围、关联实体、完成条件、状态和修订号。
- 知识：实体、关系、证据、适用版本、作者、审核状态与修订历史。
- 方案：布局、原点与朝向、材料、阶段、配置步骤、环境条件、检查规则及来源。

目标完成和归档分别记录。恢复归档不会抹除历史完成证据；恢复后重新检查当前状态。
自动条件不能因 AI 临时推断而变更，修改条件形成新修订。

## 4. 协议 v0 草案

传输与业务消息分离：游戏连接使用各加载器的自定义消息适配；本地连接使用鉴权接口。
MC 游戏端口承载客户端/服务端通信，Web 和 MCP 仍通过本地核心服务接入。

逻辑请求示例（不约束最终线上编码）：

```json
{
  "protocol": "0.1",
  "request_id": "unique-id",
  "session_id": "negotiated-session",
  "operation": "inventory.find",
  "timeout_ms": 3000,
  "params": {
    "item": {"registry_id": "minecraft:iron_ingot"},
    "scope": "player",
    "limit": 20
  }
}
```

响应包含 request_id、状态、结果或结构化错误，必要时附状态修订号与过期标记。
身份和权限来自真实连接，不接受请求自报身份授权。断线后 session 失效，写操作不得自动重放。
重复写请求通过幂等键识别；长任务返回 task_id，并支持进度、取消和终态查询。

首批操作：

| 操作 | 语义 |
| --- | --- |
| session.describe | 协商协议、会话、环境、能力和权限上限 |
| context.read | 有限读取当前界面、指向对象和个人状态 |
| item.search / recipe.query | 精确或名称搜索，分页返回来源与配方条件 |
| quest.query | 查询可见任务和进度，缺少适配时明确返回不支持 |
| inventory.find | 按范围、物品/标签查找，限制容器数、条目与时间 |
| knowledge.manifest / fetch | 获取权限过滤后的清单、修订和内容块 |
| contribution.submit | 提交带来源的社区补充，默认未确认 |
| goal.create / update / archive / restore | 带修订检查的目标管理 |
| plan.preview / inspect | 创建投影、检查布局与条件，不放置方块 |
| build.start / pause / resume / cancel | 在有效预览与授权基础上执行阶段 |
| task.get / cancel | 查询或取消长任务 |

能力缺失、权限不足、资源冲突、缺料、过期预览、范围超限、断线与版本不兼容使用独立错误码。
动态游戏查询仅访问允许且已加载的区域，默认不因查询加载或生成区块。
大消息限长、分块、限速、支持取消；具体块大小由版本适配决定，不能统一假设。

## 5. 告示牌投影与搭建流程

1. 玩家选择方案，绑定告示牌位置、维度、朝向；服务端保存绑定和所有者，牌面只显示摘要。
2. 显示投影，可调整原点和朝向，提供材料、冲突与关键原理提示。
3. 玩家检查后选择继续手动搭建，或请求自动搭建；打开投影不表示同意修改世界。
4. 木棍右键锚点作为交互入口；首次打开预览/控制，搭建必须单独明确触发，不能一次点击同时预览并执行。
5. 服务端重新检查模式、权限、范围、材料和冲突，逐阶段执行。默认从玩家背包扣料，其他库存需明确指定。
6. 暂停、缺料、冲突或区块卸载时保留进度；不自动拆除已有方块，不承诺通用撤销。
7. 分别记录方块放置完成、配置完成和设施验收结果，未支持的实体引入或配置步骤交由玩家完成。

四档为玩家期望模式，执行时与服务端允许能力取交集；非消耗搭建单独授权。
破坏锚点默认停止任务并保留记录，不继续后台施工；恢复绑定需要重新预览检查。
任意库存与世界修改无法天然形成数据库事务：实施时必须设计步骤日志和失败恢复，避免重复扣料或复制物品。

## 6. 知识同步与贡献

服务器发布权限过滤后的清单和内容哈希，玩家按需或完整下载可见内容；断线后允许阅读缓存并标明同步时间。
共享知识、公共目标动态进度、临时游戏状态分开同步，避免每次库存变化都发布知识库版本。
未批准贡献可见且可参考，不能自动覆盖已确认规则；冲突保留双方证据。
个人备注作为本地覆盖层。服务器确认、撤回与失效状态也参与增量同步。
秘密信息不下发；已下载数据不能保证撤回。截图、个人坐标等不自动进入公共知识库。

## 7. 实施顺序与验收

1. 独立服务与协议骨架：真实 1.20.1 会话查询、身份隔离、能力协商；Web 与 MCP 读取相同结果。
2. 引导闭环：选定一种配方查看器与一种任务适配，完成标记、查询、带依据回答、目标归档恢复。
3. 多人共享：MC 连接中转知识、增量缓存、未确认贡献显示、公共目标权限隔离。
4. 投影：一个经过验证的方案，告示牌绑定、旋转定位、冲突检查；不包含隐式放置。
5. 可选搭建执行：同一方案验证四档、缺料暂停、重复请求、断线及中途失败恢复。
6. 旧版验证：先 1.12.2 再 1.7.10，通过同一协议验收；开发早期用旧版物品样例验证数据模型。

AI 角色实体、寻路、多 agent 调度、RTS 界面、通用机器诊断和公共跨服知识平台不计入首版验收。
