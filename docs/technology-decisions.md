# 技术决策

日期：2026-10-25。状态：选型已确认，实现与发行验证尚未完成。

## 核心服务

使用 Python 3.12、FastAPI、Pydantic。独立运行，不导入 AMCL 的界面或要求启动器进程存在。
SQLite 存储知识实体、关系、证据、目标和修订；截图、方案与原始资料放在受控文件目录。
本地接口使用 HTTP 与 WebSocket，默认仅监听回环地址并鉴权。
请求处理与后台导入、计算任务分离；异步 I/O 不作为 CPU 计算加速手段。

## 游戏端与跨版本

首发 Java 17、Forge 1.20.1、Gradle；1.12.2 与 1.7.10 使用独立适配和适合其环境的工具链。
协议共享不意味着共用现代 Java 字节码或游戏 API。MC 自定义消息承载多人通信，世界修改由服务端校验。
现有 bridge-mod 只在来源、许可与功能核验后迁移，不直接复制整个工程。

## Web 与 MCP

使用 TypeScript、React、Vite；生产静态文件由核心服务提供，首版不额外维护 Node 服务。
使用官方 Python MCP SDK，工具调用同一应用服务；本地 stdio 接入和服务连接模式在协议实现时细化。
读取已缓存知识不要求模型。模型与外部资料作为可选提供方接入，不绑定某一家 Agent 框架。

## 原生计算扩展

配方规划先建立可替换接口和 Python 正确性基线。实际出现 CPU 热点后优先评估 Rust + PyO3；
已有适用 C++ 库时可评估 pybind11。批量跨语言传参，避免每个节点一次回调。
原生模块不访问游戏世界或绕过权限；算法仍须有预算、深度限制、取消和截断原因。

## 检查与发行

服务端用 pytest、Ruff；Web 使用 TypeScript 检查，交互测试按实际功能补充；Mod 使用 Gradle 构建和实机验证。
依赖版本和锁文件在创建真实构建工程时固定，不在空目录中伪造可运行命令。
目标为 Windows/Linux 打包核心服务加 Web 静态文件，具体打包器与平台产物需后续验证。
初期不引入向量数据库、专用图数据库、Rust 构建链或多 agent 调度框架。
